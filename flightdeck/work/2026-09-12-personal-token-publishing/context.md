# 上下文

用户希望后续由代理直接导入本地 Markdown 投稿，要求开放新建分类等缺失权限。此轮交付是 Blog 权限能力及相关验证，不创建真实投稿、不默认部署生产。

用户随后要求“有啥缺口？看看能不能处理”并确认继续，范围延伸到 Blog 正式依赖和构建缺口。本地配置修复与固定 Foundation 候选验收已授权；没有明确远端 tag/version 发布授权。正式发布按 Foundation docs/release-policy.md 执行，已准备固定 go/v0.5.0 候选及 Blog 依赖升级补丁。Provider 旧正式版本缺 PAT 的事实须保留，不能将此次 Foundation 独立编译通过解释成完整部署已就绪。

- PAT 必须同时满足显式端点准入、已选择的 scope、账号当前角色与对象归属。
- 分类治理属于 Blog 管理员能力；普通作者可创建标签，但不得借 PAT 获得分类治理或其他作者权限。
- 复用 Identity 动态权限目录和 Asset 正式 SDK，不新增凭据实现或产品内媒体协议。
- 检查发布、更新、正文与封面上传、文章分类、标签和系列归属组成的实际投稿闭环；站点设置和用户授权管理不属于投稿权限。
- 验证包含 Go 授权/HTTP 回归，以及 CLI Playwright 对动态权限选择和相关界面的实际检查；区别正式依赖、本地运行与生产状态。
